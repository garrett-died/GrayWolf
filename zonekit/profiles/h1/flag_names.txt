# Surface type names of Modern Warfare Remastered (profile h1), read as data (SurfaceTypes.h). Rows: kind|name|value[|bo3 name]
#   surface_bits   the material's surface word is a BIT SET, not an enum: the u64 at material +0x20 (value unused). A bit n set means the surface type n.
#   game           the game id the materials sidecar names for this profile (value unused)
#   surface_bit    a surface type: bit <value> of the word. The fourth field is the Black Ops III surfaceType the name maps to (a material.awi combo value);
#                  empty: no BO3 name is near enough, the name is carried as it is and the exporter says surface_unmapped (never guessed).
# Names: the table the SP executable ships as plain strings (file offset 8,184,664 of h1_sp64_ship.exe), in order; bit index = position, bark = 0. See docs/hydrax-port/mwr-materials.md
# section 12.5. proven: bits 1..4, 8, 11, 12, 15..18, 21, 23..25, 27, 28, 51 (an impact_<surface> material carries exactly that bit; MP and SP agree on 98.7% of shared materials);
# tested: bits 5..7, 9, 10, 13, 22, 26 (name keywords on the materials that carry them); the names of bits 0, 14, 19, 29..50 come from the exe's list order and fit the
# per-bit name evidence (bit 39 stickers/blinds/barrels = metal_thin, 37 containers = metal_hollow, 46 water decals = water_ankle); hypothesis: bit 20 water.
# The MP executable has none of these strings (its table is not plain), so the SP list is taken for both (the words agree).
# BO3 mapping (hypothesis where a variant is folded): a _wet or _debris variant maps to its base, _solid and the bare name to the base,
# hollow, thin and vehicle to metalhollow, metalthin and metalcar (stock BO3 GDTs use them), grate to metalcatwalk (the nearest grating), ankle and knee water to watershallow.
